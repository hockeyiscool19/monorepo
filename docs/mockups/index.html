How to choose

Every mockup is the same screen with the same markup as the neutral reference; only tokens.css and components.css differ, and every style passes the same contrast checker. So the choice is about fit, not correctness.

Expressive
consumer and mobile-first products; rounded, colorful, springy.
Editorial
reading, docs and marketing; typography-led, one accent, sharp edges.
Dense
dashboards, admin and developer tools; compact, keyboard-first, data-heavy.
Brutalist
utilities and tools that want to look honest; raw, high-contrast, few effects.
Organic
wellness and habit products such as Vale; soft shapes, warm palette, calm motion.
Nordic
the Eisenhold portal, games, lore and archives; carved frames, parchment by day, a rune-gold night HUD.
  1. Judge at 360 px first, then 1280 px, then toggle Dark. A style that only works at one width or in one theme is not finished.
  2. Check what stays readable: badge text, the muted meta line, the focus ring on the primary button (Tab into the frame), the table at 360 px.
  3. Pick by audience and content, not by novelty. Record the decision in docs/EXECUTION_PLAN.md; the portal then adopts that style's tokens.css.

Dark reaches into a mockup only when this page is served over HTTP (from the repo root: python3 -m http.server 8080, then http://localhost:8080/docs/mockups/). Opened as a file, use the mockup's own "Dark mode" button instead.
